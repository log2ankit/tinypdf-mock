Mock API control page

Watch the requests this server receives, change its routes and faults while it runs, and send test requests. Everything stays on your machine.

Target

Local server

  1. In a terminal, run npx tinypdf-mock . It needs Node.js 18 or newer and installs nothing else.
  2. Paste the address it prints. It looks like http://localhost:4747/#k=…

The server runs on your own machine and this page talks to it directly; nothing passes through TinyPDF. If your browser refuses the connection, open the control page the server prints (http://localhost:4747/__mock/): it is this same page, served from your machine.

Point your app or service at

Every request it receives shows up under Requests received. Changes to Server behavior and Mock routes apply to the running server straight away.

1. Request

Simulator paths: /items /items/1 /secure /status/503 /delay/1500 /headers, plus your own mock routes. Press Ctrl+Enter to send.

The local server sends this request for you, so any address works, including your own API on another port. There are no CORS limits and no blocked headers. Press Ctrl+Enter to send.

Your browser sends the request straight to this address, so the server must allow cross-origin requests (CORS). Nothing is saved, but do not paste secrets you would not type into any web page. Response headers the server does not expose to browsers will not appear, and that can include Retry-After.

4. Mock routes

Your own endpoints, checked before the demo routes. A path can hold parts like :id. A body can use {{params.id}}, {{query.q}}, {{body.name}}, {{now}} and {{uuid}}.

To serve these routes to a real app, download mock.json and run npx tinypdf-mock in the same folder.
